# Whiteboard Video
> 0.6.0优先修订：执行 [多插画、浅立体与混合入场](harness/COMPOSITION-DEPTH-MIX.md)。默认4～7个完整群组，使用20套可调整布局；单组面积上限35%，有效区占用目标60～85%（机器下限60%），主体短边起点15%；最多三分之一群组可fly/fade，手绘对象不能半途淡入补齐。旧文中的全手绘、85%硬下限、20%尺寸要求由本条替代。画风升级为结构完整、带有限透视/厚度的讲解漫画。


将要表达的意思转成成熟说明插画与连续的白板动画。这个独立插件维护11项配方，不接管其他视频工作流，不把本插件风格规则推广为所有视频的默认风格。

## 制作前强制更新（第一步，不可跳过）

先读 [宿主执行协议](references/HOSTS.md)，确认当前是Codex还是WorkBuddy。每次用户开始或继续视频制作任务，先运行本Skill所属插件根目录的命令（把host占位替换为实际值）：

```sh
python3 <plugin-root>/scripts/update_latest.py --host <codex或workbuddy>
```

此步骤在理解/规划新画面、生成素材、调用 OpenFilm/ChatCut 或渲染之前执行。固定从 `https://github.com/SwainWong/swainwong-whiteboard-video-plugin.git` 的 `main` 获取最新提交，按宿主适配安装入口并逐文件核验；Codex使用正式安装器，WorkBuddy使用独立本地Skill入口，无Codex CLI依赖；不以版本号相等或上次成功代替本次联网。

- 成功后必须打开返回的 `skill` 和全部 `required_read` 文件，以最新内容替换当前对话加载的旧规则，再继续制作。后续命令使用返回的 `plugin_root`。不能只更新磁盘而继续依照旧上下文。
- 网络、Git、当前宿主安装或身份校验失败就停止制作并报告具体原因；不得静默使用旧版本，不需要再次询问是否升级。
- `project.py --host <codex或workbuddy>` 的 init/check/render/capture-stage CLI 也会先执行相同更新并转交最新入口。直接 npx 或内部 Python 函数是开发接口，不能作为生产绕行路径。
- 更新不会覆盖已有视频工程的自定义 runtime、素材或剪辑。继续旧工程时记录其 runtime 版本；需要新运行时能力时创建新工程并显式迁移，不能把插件已更新说成旧工程已迁移。
- 此机制由 Skill 指令和正式 CLI 共同执行，不是任一宿主的全局启动钩子；已经加载旧版 Skill 的会话需先手动运行一次新版更新入口并重读返回文件。

## 接收与执行

沿用用户已给的主题、文字、对象、画幅、时长、语言和授权；只询问确实缺失且影响结果的信息。文字语义必须明确，图片可以补充参考，不能替代“这幅画要解释什么”。已有内容明确时直接准备和执行，不为每个岗位或阶段另设批准步骤。

先读 [输入输出合同](../../docs/INPUT-OUTPUT.md) 确认输入角色和实际运行接口。选择效果时查 [11项动画目录](../../docs/ANIMATION-CATALOG.md)，只读取选中效果的详细参考。绘画或写字前读 [资产与笔画准备](references/assets-and-writing.md)；每次生产执行 [风格与连续性Harness](harness/HARNESS.md)。

运行命令和可编辑工程位置见[安装与渲染](../../docs/RUNNING.md)。正式自定义任务走project.py check/render；直接npx和runtime结构检查属于开发低级接口，不能替代素材和来源验收。D10必须通过wrapper核对源视频指定帧和PNG实际像素，不能仅校验provenance字段格式。

整体流程：理解文字语义 → 选一个足以说明意思的对象/关系 → 准备有来源的路径或成图 → 按口播cue和阅读时间排动作 → 运行校验和渲染 → 查看受影响运动窗口 → 交付源文件、视频和实际未覆盖项。

## 不可混淆的边界

- `referenceOnly`仅供看风格/理解内容；`runtimeAsset`进入渲染；`existingFinishedSnapshot`必须来自真实已完成stage且携带来源身份。参考图片不自动成为可用运行素材。
- JPEG/PNG不包含真实笔顺。逐笔画需要有序路径；字形外轮廓描绘与汉字真实笔顺是两种方法，命名和输出必须如实。生成图片也不等于生成了绘制过程。
- 预算不足时减少完整次要对象、冗余文字，或换完整简化轮廓；必需对象仍画不完就返回缺口，不能留下半张图或无限加速。
- 手部跨相邻动作连续移动，无逐对象淡出。推图使用校准的照片质感手臂；生成的照片质感素材不冒称真人实拍。
- 总览只能纵向展开真实已完成stage，不能新造示意卡片冒充历史画面。不存在额外的十stage巡览动画。

## 交付与判断

交付实际可调用输入、资产来源、运行版本、视频、可编辑工程和验证记录。缺素材/路径/快照/必要时间时拒绝对应渲染并给出最小修复，不把说明文档当完成产物。输入验证、渲染解码、像素观察、正常速度观感和用户确认分别记录。

角色分工是制作建议，单个Agent可按任务规模承担，不强制派齐人员或另开会话。角色输入→处理→输出→交接见[整体工作流](references/workflow.md)。

## 整片平台与展示层
新整片制作必须读取并执行 [展示层合同](harness/PRESENTATION.md)，运行其中配置校验后方可交付。它只管理固定屏幕层及平台选择，与D01–D11世界层分别工作。

SwainTalk片头片尾读取 [连续画布品牌站](harness/BRAND-STATIONS.md)：原Logo与精确口号位于同一世界画布，镜头连续进入正文/离开正文，品牌展示时隐藏绘画手。它是整片宿主合同，不增加动画配方或冒称自动渲染API。

## 默认绘画风格
每次资产准备必须先读 [粗线平涂讲解漫画](harness/DRAWING-STYLE.md)，将style ID、tokens、实体特征与参考角色传入同一style packet。后续模型/Agent沿用该packet并按验收表实看输出；不是仅写“手绘”关键词。

## 开场节奏与逐句画面（0.3.0）

任何新制或修订整片先读 PRODUCTION.md / BRAND-STATIONS.md 和 [制作检查合同](../../docs/PRODUCTION-CHECK.md)：先3–5句主题引入，期间无频道品牌；再说出频道名和精确slogan，与品牌动画对齐；正文每个完整口播句至少一个对应的新绘制或笔刷显图动作，不能按音频段落共用静态图标。相关句可在同一画布连续增画，不机械切页。

最终音轨逐句登记到 narration.json，production.json绑定该清单、资产和brand时码；presentation.json必须指向production_path。批量制作前运行 `python3 <plugin-root>/scripts/check_presentation.py PROJECT/presentation.json --mode plan`，交付前运行 `--mode delivery`。不通过就修复对应句/时码，不能用仅渲染成功、保留旧音轨或静态图充数。缺真实听看证据保留未验收状态，不编造review PASS。独立D01–D11素材开发不强制全片品牌。

## 全程笔触、直接实体和无限画布（0.4.0）

整片制作或修订先读 [PEN-SEMANTICS-CANVAS](harness/PEN-SEMANTICS-CANVAS.md)。纸面轮廓和文字须沿路径绘制；颜色可与画笔动作协调地快速扫过并限制在目标轮廓内；先登记并核查每个对象所有目标色面及有意留白，扫色方式不得决定哪些部位上色；第三方图使用笔刷遮罩。禁止半途淡入补完、自动填色、预设标题。按口播具体实体选择原Logo、可辨认肖像和明确角色动作，不用通用符号代替指定对象。对象不限数量、不用固定三槽；记录同一世界坐标中的自由布局、避碰和按语义推进的连续相机路线。

使用production v2实体/元素/笔触/canvas清单；新D01 `scene.pen` 支持实际路径上墨、涂色和图片笔刷遮罩，见 [笔触程序](../../docs/PEN-PROGRAM.md)。旧draw.fillAt、矩形扫色、渐入/摆图不满足严格整片默认。更新已有工程须显式迁移并检查，不能只升级插件就沿用旧绘制实现。screenLayer字幕、导航及既定品牌站保留各自特例，正文图解不能借此绕过。

## 注意力与独立语义评审（0.5.0）

整片必须执行 [注意力与独立语义评审](harness/ATTENTION-SEMANTIC-REVIEW.md)：单对象涂色最多三遍、默认1.5秒内；离开正文区域前有效内容占用至少85%；主体尺寸和320px整帧可读性同时检查。逐目标比较至少两种图像联想，调用独立新上下文子Agent先盲识别再对口播评分，未通过不得由作者自评放行。production必须有attention清单；缺实际视听证据如实保留未验收。
