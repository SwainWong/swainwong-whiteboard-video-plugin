# SwainWong Whiteboard Video

把讲解文字、插画和资料图组织成连贯的 **Whiteboard Animation（白板动画）**，交付可编辑的 Remotion 工程与视频。

这是独立插件，入口是 `$whiteboard-video`。它维护11项动画方法及配套输入、素材与检查规则，不依赖原视频制作插件，不附带第三方参考片。照片质感手臂为生成资产，不能标作真人实拍。

## 每次制作前自动更新

版本 **0.2.0** 起，Skill 的第一步是运行 `python3 scripts/update_latest.py`。工具每次直接从 GitHub `main` 获取最新提交，通过 Codex 安装器更新，并核对安装文件与远端源码打包结果。成功返回当前版本、提交和最新规范路径，Agent 必须重新阅读后才进入制作。网络或升级失败时停止，不能退回旧版继续。

`project.py` 的正式命令也会先更新，再调用最新安装版本。更新独立保存于 Codex home 下的 `whiteboard-updates/`，不会修改源码 checkout 或覆盖已有影片工程。已有工程的自定义运行时保留原样，不能将插件升级当作工程迁移。已经运行中的旧会话需要先执行新版入口并重读规范；插件不提供 Codex 全局启动钩子。

[更新机制与故障处理](docs/RUNNING.md#制作前更新)说明首次安装、执行边界和验证记录。

## 整体怎么用

给出主题与素材 → 写3–5句主题引入 → 安排与口播同步的频道品牌段 → 按完整口播句设计画面 → 准备路径或图片 → 检查逐句覆盖与时间 → 渲染并实际听看 → 交付工程与视频。

单句可以只画一个足以说明意思的对象；整片每句都要有对应的新绘制或笔刷显图动作，不能用一个静态图标支撑一整段。文字、卡通、图形、照片都能进入白板，但进入方式不同：逐笔绘制需要路径；严格整片中的多数原图用笔尖驱动的局部遮罩逐步显露，最多三分之一群组可直接fly/fade，独立素材目录仍保留其他入场配方。图片不是笔顺，生成图片也不是绘画过程。

## 安装与开始

需要 Node 22+、Python 3.10+、npm、FFmpeg/ffprobe。构建本地marketplace后安装插件，再创建独立的可编辑视频工程。

```sh
python3 scripts/package_plugin.py
codex plugin marketplace add ./dist
codex plugin add swainwong-whiteboard-video-plugin@swainwong-whiteboard-local
python3 scripts/project.py init ../my-whiteboard-video --install
```

[运行说明](docs/RUNNING.md)包含场景校验、渲染、真实完成帧提取和浏览器兼容处理；每次输出使用新文件名，避免覆盖已有视频。

## 内容与分镜

**接收**讲解文字、要解释的对象、时长或口播cue，以及参考图片。

**处理**每句究竟需要什么画面；先以3–5句配主题视频/卡通/图片引入，期间不出现频道Logo、水印或slogan；随后让频道名与口号配音对齐品牌动画，再进入正文逐句绘制。

**输出**完整口播句清单、品牌短语时码、具体实体/动作目标、至少两种图像候选及选择理由、画面事件，交给资产准备。相邻句可在同一画布增画，字幕、保持旧图和镜头移动不单独计作画面覆盖。

## 资产与笔画

**接收**对象、画风、参考与绘制要求。

**处理**成熟说明插画、可用照片、有序路径或字形轮廓；把参考图、运行资产、真实完成stage快照分开登记。准备透明手臂及笔尖/接触点校准。

**输出**可用资产、身份参考、辨识特征、轮廓/涂色笔触、来源和锚点，交给动画实现。没有路径的成图不会被假装成真实逐笔绘制。

## 动画与渲染

**接收**效果输入、资产、布局和时间。

**处理**先逐对象列出所有目标色面和有意留白，再执行路径绘制、快速扫色、笔刷显露原图与手部连续移动。扫色方向独立于上色区域；逐项对照目标图检查是否漏掉任何必要面。使用D01的scene.pen，轮廓与笔尖同步，色面以相同时间进度快速扫显；不在结束时突然补色。宿主按统一世界坐标组织不定数量对象、检查占用范围并实现多方向连续相机，不复用三槽布局或PPT滑页。口播时间不足时减少完整内容或换完整简化画法；必要部分仍容不下就报出缺口。

**输出**输入JSON、工程、视频和技术验证，交给画面检查及下游剪辑。总览只沿纵向展示实际已经完成的stage，不新造卡片。

## 画面检查与交付

**接收**当前视频、文件身份和来源记录。

**处理**先运行逐句制作、实体/元素/世界画布与展示配置检查，再实际听看开场、频道口播同步及每句语义对应；先核对涂色遍数/耗时、离开前85%有效区占用和主体尺寸，再让独立子Agent先盲识别、后对口播评分；检查每个元素未画前、轮廓中、涂色中、完成及保持，核对直接所指、笔尖接触、纸面文字与全部镜头过渡；检查自然手绘边缘、可替换图片节点、时间预算及总览来源。改变内容或时序后复查受影响窗口。

**输出**实际检查范围、具体问题与修复结果，交给用户确认。输入校验、渲染成功、局部像素检查、正常速度观感和用户接受分别记录。

这些角色是组织工作的建议，不要求每次派齐Agent或重复请求审批。完整分工见[工作流说明](skills/whiteboard-video/references/workflow.md)。

## 可移植性与当前边界

运行素材使用项目public目录相对路径；字体文字应先变成可移植路径，并保留字体或笔顺来源。项目可用内置原创样例，也可换任意合法准备好的图片与路径。插件不提供“任意JPEG自动变真实笔顺”或“任意布局自动布线”。

D09当前为向下曲线分支；D10使用带原视频/帧/哈希的完成PNG，仅纵向排列；D08/D11的字形由调用方提供，背景颜色可配。具体实现能力和限制以[输入输出合同](docs/INPUT-OUTPUT.md)及runtime类型为准。

## 长篇制作与发布规则

[Production harness](skills/whiteboard-video/harness/PRODUCTION.md) 将逐句口播映射到有机画布上的简笔画与资料图，规定对象辨识、连续手部与可验证的交付。输入为 brief、口播时间、来源和品牌资产；输出为 cue map、动画输入、审核证据与发布包，交给动画、剪辑和发布环节。

SwainTalk 封面配置使用右下角商标、清晰短标题和可辨认的人物/产品。标题与描述须贴合成片；不承诺关键词避让能保证推荐或广告收益。OpenFilm / Video Factory 对接仅在项目要求时使用，不是插件内置依赖。

## 整片展示层与制作平台

[展示层合同](skills/whiteboard-video/harness/PRESENTATION.md)接收平台、最终音轨时钟、章节、字幕语言和原Logo，以独立屏幕层组织顶部进度、底中短语字幕与右下透明水印。输出展示配置和检查报告交给用户选定的OpenFilm或ChatCut合成；双平台分别验收。Remotion继续生成白板动画素材。

整片先准备v2 [production.json 制作清单](docs/PRODUCTION-CHECK.md)，再复制[参数配置](docs/presentation-profile.json)到项目的layout字段，按合同准备presentation.json，然后运行 `python3 scripts/check_presentation.py /path/to/presentation.json --mode plan`。批量制作前plan检查开场句数、品牌时码和逐句覆盖；交付前delivery模式要求当前候选与实际听看记录。校验不自动装配平台，也不独立识别画面语义或替代最终听看。该合同不会将白板改成纸艺或强制第三方满屏；封面Logo与视频水印独立。

## SwainTalk 片头与片尾

[连续画布品牌站合同](skills/whiteboard-video/harness/BRAND-STATIONS.md)接收原Logo、固定口号、画纸色、正文首末镜头状态和实际音轨时间。在3–5句主题引入后，以实际“SwainTalk. Follow the tech. Follow the money.”配音驱动品牌显现、可读停留、镜头移入正文与片尾返回品牌；首尾品牌展示时隐藏绘画手，正文保持连续绘制。输出品牌站配置、宿主实现和边界听看证据，交给所选平台合成。当前是明确的制作合同，未新增自动整片相机API；无新增D12配方。

## 默认手绘画风

[粗线平涂讲解漫画 Harness](skills/whiteboard-video/harness/DRAWING-STYLE.md)定义粗黑轮廓、鲜明平涂、夸张但可辨认的人物和功能物件，以及有主次的有机图解。输入是口播语义、实体特征、参考图与统一style packet；输出是可编辑图层/路径或明确命名的成图，再交给动画制作。包含参数起点、跨模型提示词、禁止项和逐项视觉验收。真实手臂、品牌与固定字幕仍遵守各自合同。

用户提供的第三方风格截图仅用于分析，不随仓库分发。文字规范和参数不能保证任意模型直接产出完全一致画面；模型切换须校准样张并检查实际输出。

## 全程落笔与无限画布（0.4.0）

[严格绘制合同](skills/whiteboard-video/harness/PEN-SEMANTICS-CANVAS.md)接收逐句实体、身份参考和绘制内容，要求轮廓和纸面文字沿路径绘制，色面随画笔动作快速扫显，第三方图片由笔刷显露。指定机构、品牌、人物和产品使用可辨认的标志、肖像或外形参考；泛化替身、半途补色、预设标题和固定三槽不能通过实际审阅。

[scene.pen笔触程序](docs/PEN-PROGRAM.md)提供可运行的描线、局部涂色和图片遮罩，输出素材交给宿主。布局按语义保存世界坐标和连续相机路线，不以对象数量或固定方向决定分页；全片相机与跨素材手部接续仍由宿主实现。新检查器核对production v2目标、笔触绑定、占用框与相机记录，交付检查还要求当前候选的实际审阅证据。

旧D01自动填色、D08/D11矩形扫色和淡入/摆图仍可做独立机制演示，须按当前混合入场额度及语义要求使用。已有影片须显式迁移；没有自动生成任意实体笔顺、自动认脸或自动验收画风的能力。

## 注意力预算与语义评审（0.5.0）

[注意力合同](skills/whiteboard-video/harness/ATTENTION-SEMANTIC-REVIEW.md)要求单对象涂色最多3遍，默认着色耗时不超过1.5秒；正文离开当前区域前，语义主体紧占用框并集达到有效区60～85%，主要主体短边至少为有效区短边15%，并检查320px整帧可读性。优先放大、取近景或继续相关内容，不能添加无关图案凑面积。

独立联想模块接收逐句目标与参考，比较直接图像候选，交新上下文子Agent盲识别后再核对口播；四项评分各至少4/5且总分至少17/20。输出原始审阅记录交动画修订和最终审片。新增 [attention清单](docs/ATTENTION-CHECK.md)由现有plan/delivery入口检查；脚本核对声明值和证据身份，不自动调用模型、辨认画面或证明用户验收。

## 多插画、浅立体与混合入场（0.6.0）

[当前构图合同](skills/whiteboard-video/harness/COMPOSITION-DEPTH-MIX.md)优先于旧版全手绘/85%硬下限。内容岗位划分4～7个完整语义群组，布局岗位从 [20套位置与数量方案](docs/layout-catalog.json)按需选择并调整，资产岗位制作粗轮廓、完整结构、有限透视与厚度的讲解漫画。主图不再撑满视口，保留群组间留白和320px可读性。

动画岗位为至少三分之二群组安排手绘，其余可fly/fade，记录资产、时序及退出方式，交宿主统一世界画布合成。独立评审同时核对语义与结构/空间/细节，检查器核对布局ID、数量、面积、入场比例和评分记录。布局数据提供起点，不自动替宿主完成构图或飞行动画；旧片须显式迁移。
